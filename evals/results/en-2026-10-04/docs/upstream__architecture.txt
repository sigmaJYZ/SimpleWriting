sqlpipe is a three-stage pipeline that copies Postgres tables to S3 as Parquet files, and each stage hands its output to the next through a bounded queue. The reader process opens a connection to Postgres and streams rows in batches, so it never loads a whole table into memory. The converter receives each batch and encodes it as a Parquet row group (a block of rows stored together by column). It adds the row groups to a file until the file reaches a target size. The uploader then writes each finished file to S3 as a multipart object (an object sent in separate parts). If a part fails, the uploader retries it with increasing delays. If all retries fail, it aborts the upload and reports the error. Because the queues have a fixed size, a slow uploader makes the reader wait, and this keeps memory use steady.
