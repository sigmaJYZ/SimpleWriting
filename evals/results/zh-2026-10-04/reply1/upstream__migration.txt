回填（backfill）是指给表里已有的行补上新列的值。你的迁移卡住，很可能是因为数据库要一次性给 20 GB 的所有行写值，同时持有表锁，所以其他查询都在排队。

先停掉卡住的迁移，让锁释放。如果是 Postgres，可以在 `pg_stat_activity` 里找到该会话，再用 `pg_cancel_backend(pid)` 取消它。我不知道你用的是哪种数据库，下面的做法以 Postgres 为例。MySQL 的思路相同，但语法和在线改表工具（例如 gh-ost 或 pt-online-schema-change）不同。

安全的做法分四步。第一步，把列加成可为空，并设置默认值，这一步很快。第二步，分批回填旧行，每批几千到几万行，每批单独提交，这样锁的时间很短。第三步，回填完成后，确认没有剩余的空值。第四步，再加 NOT NULL 约束。

```sql
-- 1. 加可空列，新行用默认值
ALTER TABLE big_table ADD COLUMN new_col integer;
ALTER TABLE big_table ALTER COLUMN new_col SET DEFAULT 0;

-- 2. 分批回填，重复执行直到更新 0 行
UPDATE big_table SET new_col = 0
WHERE id IN (
  SELECT id FROM big_table WHERE new_col IS NULL LIMIT 10000
);

-- 3. 先加不检查旧数据的约束，再单独验证，避免长时间锁表
ALTER TABLE big_table ADD CONSTRAINT new_col_nn CHECK (new_col IS NOT NULL) NOT VALID;
ALTER TABLE big_table VALIDATE CONSTRAINT new_col_nn;

-- 4. Postgres 12 及以上会利用已验证的约束，跳过全表扫描
ALTER TABLE big_table ALTER COLUMN new_col SET NOT NULL;
ALTER TABLE big_table DROP CONSTRAINT new_col_nn;
```

如果你的 Postgres 是 11 或更新版本，带常量默认值的 `ADD COLUMN ... NOT NULL DEFAULT 0` 本来不会重写整张表。所以迁移卡住也可能是因为别的长事务占着锁，而不是数据量本身。请告诉我数据库类型和版本、新列的默认值是常量还是要按其他列计算，我可以据此给出更准确的迁移脚本。
